# Hello Park — Интерфейс Регистрации Гостя

Это мобильный веб-интерфейс (SPA) для самостоятельной регистрации гостей в парке "Hello Park". Интерфейс разбит на 3 логических шага и предназначен для использования преимущественно на смартфонах.

## Структура проекта

- **`index.html`** — Основной файл разметки. Содержит структуру всех трёх шагов, SVG-иконки, а также всю логику на чистом JavaScript (в теге `<script>`).
- **`style.css`** — Стили проекта (CSS3). Содержит переменные, общие стили, анимации и стили для компонентов интерфейса (степы, карточки, инпуты, кнопки).
- **`qrcode.min.js`** — Внешняя библиотека для генерации QR-кодов на клиенте.
- **`rocky.png` / `rocky.webp`** — Графические ассеты (персонаж Рокки).

## Архитектура и интерфейс (HTML/CSS)

Проект использует подход, имитирующий нативное мобильное приложение:
- Главный контейнер `.app` ограничен максимальной шириной `480px` (`max-width: 480px`), на экранах меньше он занимает `100vw`.
- Запрет на масштабирование экрана (viewport `user-scalable=no`).
- Использование "Glassmorphism" (эффект матового стекла) через `backdrop-filter: blur()`. Применяется в верхнем индикаторе шагов (`.progress-container`) и в нижней панели навигации (`.bottom-nav`).

### Основные компоненты и классы:
- **`.step` / `.step-visible`** — Секции с шагами регистрации. Переключение шагов осуществляется с помощью плавного добавления/удаления класса `.step-visible` (через opacity и transform).
- **`.progress-container` / `.progress-glass`** — Индикатор прогресса (Шаг 1 из 3).
- **`.bottom-nav`** — Фиксированная нижняя панель с кнопками навигации ("Далее", "Назад", "Получить QR").
- **`.form-group`, `.form-input`, `.phone-wrapper`** — Элементы форм. В инпутах реализованы состояния ошибки (`.input-error`) и фокуса.
- **`.child-card`** — Карточка добавления ребенка на шаге 2. Добавляется и удаляется динамически.
- **`.toast-container` / `.toast`** — Система всплывающих уведомлений (например, "Код отправлен", "Успешно").

## Логика приложения (JavaScript)

Вся логика реализована в нижней части `index.html`. Основные переменные состояния:
- `step` (от 1 до 3) — текущий шаг.
- `verified` (boolean) — статус подтверждения номера телефона.
- `smsTimer` / `smsCountdown` — таймер повторной отправки СМС.
- `childId` — счетчик для генерации уникальных ID детей.

### Описание шагов:

1. **Шаг 1 (Согласие и Телефон):**
   - Форматирование номера на лету (функция `fmtPhone`).
   - Имитация отправки СМС (открывается поле ввода 4 цифр).
   - Валидация СМС-кода (успешно при вводе любых 4 цифр, кроме '0000').
   - После подтверждения номера кнопка "Далее" активируется.

2. **Шаг 2 (Данные семьи):**
   - Ввод ФИО родителя (обязательное поле).
   - Динамическое добавление/удаление детей (Имя и Дата рождения).
   - Валидация: должно быть заполнено ФИО родителя, добавлен минимум один ребёнок, и у всех детей должны быть заполнены имена и даты.

3. **Шаг 3 (Генерация QR-кода):**
   - Формирование JSON-объекта со всеми собранными данными (ФИО, телефон, массив детей).
   - Кодирование JSON в Base64.
   - Генерация QR-кода через библиотеку `QRCode.toCanvas` с префиксом `HPARK:`.
   - Кнопки добавления карты в Apple Wallet и Google Wallet (пока только UI-заглушки).

## Для программиста (Интеграция)
1. Вся бизнес-логика (отправка СМС на реальный бэкенд, проверка кода, сохранение гостей в БД) сейчас работает как **mock** на клиенте. Вам нужно будет заменить функции `verifySms()` и обработчики кликов по кнопкам на реальные API-запросы.
2. В `style.css` не используются CSS-фреймворки (Tailwind/Bootstrap), всё написано на Vanilla CSS для легкости интеграции.
3. Библиотека QR-кодов подключается локально, но может быть заменена на любую серверную или клиентскую библиотеку в вашей экосистеме.
